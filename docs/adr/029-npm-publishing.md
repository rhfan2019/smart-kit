# ADR-029 npm 发布：导出条件、Changesets 同步版本、可信发布

- **背景**：四个包（`@rhfan2019/smart-kit-core`、`@rhfan2019/smart-kit`、`@rhfan2019/smart-kit-server`、`@rhfan2019/smart-kit-cli`）要能在其他项目里用 npm 安装（讨论记录 D23、D24）。核查发现：开发时 `exports` 指向 `src`，发布版写在 `publishConfig.exports` 里，但 **npm 不会用 `publishConfig` 覆盖 `exports`**（只有 pnpm 和部分 Yarn 版本会；npm/cli#7586），`npm pack` 打出的清单仍指向不在包里的 `src`，四个包都无法导入。peer 依赖也写成了精确版本。
- **决定**：
  - **导出条件**：每个导出项写成 `{ "smart-kit-source": "./src/…", "types": "./dist/….d.ts", "import": "./dist/….js" }`。只有本仓库打开 `smart-kit-source` 条件：`tsconfig.base.json` 的 `customConditions`、`vitest.config.ts` 和示例应用 / Storybook 的 Vite `resolve.conditions`、`apps/pg-server` 的 `tsx --conditions=smart-kit-source`。使用方不认识这个条件，走 `dist`。发布的清单就是仓库里的清单，发布前不改写任何文件（`publishConfig` 只留 `access: public`）。条件名不带 npm scope，改 scope（ADR-012）时不受影响。
  - **清单**：`description`、`keywords`（不含商标词，ADR-013）、`homepage`、`bugs`、`repository.directory`、`license`；每个包目录有 `README.md`（npm 页面）和 `LICENSE`；`files` 是 `dist` 和 `docs`（加 React 包的 `skills`，ADR-030）。peer 依赖写成测试过的版本起的 `^` 范围，AG Grid 仍是可选 peer（ADR-026 P3）。内部依赖写真实版本号（npm workspaces 不用 `workspace:` 协议）；示例应用是私有包，依赖写 `*`。
  - **版本**：Changesets（`.changeset/`），四个包放进一个 `fixed` 组，同步版本（ADR-027）；内部依赖由 `changeset version` 一起改。私有的示例应用不进版本和标签。每个包的 `CHANGELOG.md` 由 Changesets 生成；根目录 `CHANGELOG.md` 保留到 0.1.0 的手写历史。
  - **发版**：`.github/workflows/release.yml` 在 main 上的 CI 通过之后运行（`workflow_run`，CI 失败就不发布；也可以手动触发），用 `changesets/action`：main 上有未发布的 changeset 时开一个"chore: version packages"拉取请求，合并后执行 `npm run release`（构建后 `changeset publish`，只发布 npm 上还没有的版本），发布后用 `verify-pack.mjs --registry` 从 npm 安装并检查（新版本要几分钟才能安装，失败时每 30 秒重试，最多 10 分钟）。仓库设置要允许 GitHub Actions 创建拉取请求。发布用 **npm 可信发布**（OIDC，`id-token: write`，npm ≥ 11.5.1），不存 npm token，自动带 provenance。第一次发布由维护者在本机手工执行（npm 只允许给已存在的包配置可信发布者），之后在 npmjs.com 给每个包配置可信发布者（仓库 `rhfan2019/smart-kit`、工作流 `release.yml`）。
  - **打包验证**：`scripts/verify-pack.mjs`（`npm run verify:pack`，CI 每次都跑）：打 tgz，在仓库外新建 Vite + React + TS 项目和 Node 项目，从 tgz 安装，检查每个子路径的运行时导入、类型（`moduleResolution` 为 `bundler` 和 `nodenext`，`skipLibCheck: false`）、只引入 `MicroChart` 的体积与 `check-size.mjs` 一致、`styles.css`、随包文档、server 的 `$metadata` 和读取、`smart-kit` 命令。`tests/unit/packaging.test.ts` 检查清单的规则。
- **理由**：导出条件是 TypeScript 5.0 起支持的标准做法（"live types"），不需要发布前改写清单（React Native 用 `prepack` 改写，是备选），也不依赖包管理器的私有行为；打包验证从使用方的角度测，避免"仓库里能用、装上不能用"。
- **代价**：本仓库每个解析工作区包的工具都要打开这个条件，漏开时会悄悄解析到 `dist`（可能过期）。`packaging.test.ts` 和 CI 里先于构建运行的类型检查、单元测试会暴露这种情况。
- **状态**：采纳（2026-11-16）。
