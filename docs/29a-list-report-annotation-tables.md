### 最重要的 5 个问题

1. **编辑状态的默认筛选和 FE 相反（P1）。** smart-kit 的"全部"只取活动版本（`IsActiveEntity eq true`），用户新建后还没激活的草稿在列表里看不到，自己的草稿也不会替代活动版本显示。应该改成 FE 的 `IsActiveEntity eq false or SiblingEntity/IsActiveEntity eq null`，并补齐 6 个选项（`SmartListReport.tsx` 108-124 行）。
2. **好几种 LineItem 记录会让整列消失（P2）。** `DataFieldForAnnotation` 指向 FieldGroup、ConnectedFields 或 Contact 时，以及 `DataFieldWithIntentBasedNavigation`、`DataFieldWithAction`，`buildField` 都直接丢掉这一列（`bm` 558-561、579-582 行），而 FE 会显示值。反过来，FE 不显示的 `DataFieldWithActionGroup`，smart-kit 却显示成普通列。
3. **工具栏动作的集合和 FE 不一样（P2）。** `DataFieldForActionGroup` 里的子动作全部丢失；LineItem 里 Determining 的动作被放进了工具栏；`UI.CreateHidden`、`UI.DeleteHidden`、`Common.IsActionCritical`（执行前确认）、`UI.IsCopyAction` 都没有实现。
4. **可用性判断有缺口（P2）。** 非绑定动作的 `Core.OperationAvailable` 为 false 时按钮仍然可用，点了没有任何反应（`ST` 732 行）；路径形式的 `DeleteRestrictions/Deletable` 被当成 true，不按行判断；`InsertRestrictions` 也只读常量。
5. **列的外观和个性化（P2）。** 不读 `HTML5.CssDefaults/width`；不读 LineItem 上的 `UI.Criticality`，所以没有行高亮；个性化不能添加 LineItem 以外的属性；选定 SPV 或 PV 时没有"Visualizations 里要有 LineItem 或 Chart"的检查，也没有"Chart 排第一时默认显示图表"。

### 最重要的 5 个问题

1. **`Common.FilterDefaultValue` 未实现（P1）**：在 RAP 中很常见（`@Consumption.filter.defaultValue`），FE 在没有默认 SV 时用它生成 EQ 默认条件。smart-kit 完全没有读取，所以默认筛选值缺失，也影响首次执行的结果。
2. **值帮助的 In 和 Constant 参数不生效（P1）**：FE 把 In、InOut 和 Constant 作为值帮助请求的 $filter（In 的值取自筛选栏中对应字段的条件）。smart-kit 的 `buildValueHelpRequest`（`request.ts:410-442`）不加筛选，会提供不该出现的值。Out 参数也不回写（P2）。
3. **多视图只应用"各视图取值不同"的条件（P1）**：`SmartListReport.tsx:155-166,281` 把所有视图共有的 SV 条件交给默认 SV 处理，默认 SV 里没有时这些条件会丢失，表格结果出错。FE 对每个视图应用完整的 SV。
4. **搜索框默认值与 FE 相反（P1）**：FE 只要 SearchRestrictions 没有写 `Searchable=false` 就显示搜索框；smart-kit 默认 `searchable: false`（`buildModel.ts:336`）。另外，值帮助的 `SearchSupported` 默认值与词汇表不符（词汇表为 true，smart-kit 为 false，P2）。
5. **FilterExpressionRestrictions、FilterFunctions 和日期运算符只是部分对齐（P2）**：同一属性有多条限制时没有取最严格的一条；各表达式的运算符集合与 FE 不同（Empty/NotEmpty、Not* 和排除条件）；没有按 `FilterFunctions` 的 `tolower` 做不区分大小写的筛选；语义日期运算符缺少 FROM、TO、N 周/月等。HiddenFilter 和 Hidden 字段有默认条件时会被显示出来（`useFilterState.ts:73`，P2），也值得一并修复。

## 值的显示

范围：列表页（表格单元格、筛选令牌、快速预览、列标题），对象页专属行为不计。
FE 依据路径都相对于 `scratchpad/fe/modules/sap/fe/`；smart-kit 依据路径相对于 `packages/`。词汇表依据在 `scratchpad/annot/vocab/`。
本表引用的 FE 核心逻辑：
- 单元格显示方式的判定顺序在 `macros/internal/field/FieldStructureHelper.js` 的 `setUpDisplayStyle`。顺序是：IsImage → IsImageURL（Avatar）→ InputMask → Masked → Edm.Stream（File）→ DataPoint / Contact → IBN / NavigationPath → SemanticKey（ObjectIdentifier）→ DataField.Criticality（ObjectStatus）→ 金额/数量对齐 → Email/Phone（Link）→ MultiLineText（ExpandableText）→ DataFieldWithUrl（Link）→ Text，有快速预览时为 LinkWithQuickView。
- 文本排列在 `core/templating/DisplayModeFormatter.js` 的 `getDisplayMode`。

### 最重要的 5 个问题

1. **`Common.IsDigitSequence` 在筛选输入时不补零（P1，结果错）**：S/4 服务里单据号、物料号大多带这个注解。用户在筛选栏输入“123”时，FE（UI5 String 类型）会补成“0000000123”，smart-kit 原样发出，查不到数据。在 `react/src/filter/conditionText.ts` 的 `parseConditionText` 里按 maxLength 补零即可（UI5 的具体补零规则待核实）。
2. **通信类字段没有链接（P2）**：`Communication.IsEmailAddress`、`IsPhoneNumber` 在 FE 里是 `mailto:` 和 `tel:` 链接，`Communication.Contact` 是联系人弹出框；smart-kit 显示纯文本，Contact 列直接被丢弃（`buildModel.ts:579-581`）。
3. **筛选令牌的文本排列与 FE 不同（P2）**：FE 遇到 TextSeparate 只显示代码，有 Text 但没有值帮助时也只显示值；smart-kit 把 TextSeparate 改成了 TextFirst（`ConditionInput.tsx:78`、`ValueHelpDialog.tsx:150`）。
4. **单元格数值格式（P2）**：DataPoint 的 `ValueFormat.NumberOfFractionalDigits` 在单元格里没有生效（`field/values.ts`）；没有读取 CodeList 里每个币种和单位的小数位；金额和数量列没有做 FE 那样的小数点对齐；Progress 进度条没有状态色。
5. **链接与标识的语义（P2）**：外部链接一律在新窗口打开（`SmartField.tsx:143`），没有读取 `HTML5.LinkTarget`（FE 缺省在当前窗口打开）；`Common.ExternalID` 和 `Common.Masked` 没有实现，会显示内部 GUID 或明文敏感值；快速预览缺“经导航取目标键”这条规则。

另外有两处文档或注释和代码对不上：`docs/02-annotation-coverage.md` 第 3 节说支持 `Measures.Scale`，实际用的是 Edm Scale facet；`textArrangement.ts:7` 的注释说 TextSeparate 会让文本单独成列，代码并没有这样做。

### 最重要的 5 个问题

1. **草稿列表的"编辑状态"和默认请求与 FE 不同（P1）**：FE 的"全部"是 `IsActiveEntity eq false or SiblingEntity/IsActiveEntity eq null`，自己的草稿代替活动实例出现在列表里；smart-kit 永远只列活动实例，"自己的草稿 / 他人的"也用活动实例上的标记表示。另外选项数量和含义也不一样（FE 有"被他人锁定"和"他人有未保存的更改"，按 `InProcessByUser` 判断）。依据：`DraftEditState.js` 和 SmartListReport.tsx:109-124。
2. **CustomAggregate 被忽略，图表和合计一律 `with sum`（P1）**：FE 的分析表格、图表、KPI 都以 `Aggregation.CustomAggregate` 为准，请求 `aggregate(M)`；smart-kit 的合计和图表都用 `M with sum`，判断依据是 AggregatableProperties 加数值类型。平均值、比率、去重计数之类的度量会算错，有的服务还会拒绝这种请求。依据：`Table.js` `rt`、`helpers/Aggregation.js`；request.ts:397、totals.ts:27-36。
3. **列表页图表与 FE 差距大（P2）**：只画第一个维度和第一个度量，除 Bar 以外都画成柱状图，不用 PV 的 SortOrder，不支持 DynamicMeasures / AggregatedProperty，不显示 Chart.Actions，标题不用 Chart.Title。依据：ChartView.tsx:44-45,74；request.ts:393；`ChartHelper.js`、`MdcChartTemplate.js`。
4. **多视图模型与 FE 不同（P2）**：smart-kit 自动收集所有带限定符的 SPV，每个视图都是"表格 + 可切换的图表"；FE 由 manifest 指定视图，视图可以是 SPV、PV 或 SV，可以指定实体集，引用 Chart 的视图是单独的图表视图。smart-kit 还有两处偏差：视图没有排序时回退到默认 PV 的排序；视图的 RequestAtLeast 不生效。依据：`ListReportConverter.js` `dt`/`et`；buildModel.ts:731-748。
5. **注解驱动的自动判断缺失（P2）**：FE 会根据注解自动选表格类型（ApplySupported 支持全部 8 种转换 → AnalyticalTable；有成对的 RecursiveHierarchy → TreeTable），用 PV 的 InitialExpansionLevel 和 MaxItems 决定层级表的初始展开和每页行数；没有 `Total` 时默认合计所有可聚合列；删除确认显示 HeaderInfo.Title。smart-kit 这些都要手工设置或者不支持。依据：`Table.js` `bn`/`jt`/`zt`/`Kt`、`TableEventHandlerProvider.js`；SmartListReport.tsx:219、SmartTable.tsx:543,560,1227。
