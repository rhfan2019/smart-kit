# ADR-026 打包规则：用多少付多少；React 包按领域分子路径

- **背景**：用户的原则是"不要犯 SAPUI5 的错误：太重、加载奇慢"（讨论记录 D14）。UI5 慢在三处：运行时按命名空间逐个请求模块和主题文件；用一个控件要加载整个库；先等 `$metadata` 下载和解析才开始画。2026-11-16 实测：应用只引入 `MicroChart`，打包后约 505 KB（gzip），与引入 `SmartTable` 一样，AG Grid、Mantine 和整个 smart-kit 都被带进来。原因是 ADR-004 的构建输出单个 `index.js`，而且 `SmartTable.tsx` 在模块顶层注册 AG Grid 模块（副作用）。
- **决定**（P1～P8，D14）：
  - **P1** 只在构建时打包，只输出 ESM，运行时不按需去服务器拉模块（沿用 ADR-004）。
  - **P2** 用多少付多少：构建保留源文件结构（`preserveModules`，一个源文件一个输出文件）；模块顶层不做注册、不改全局；`package.json` 的 `sideEffects` 只标 CSS。
  - **P3** 重依赖隔离：AG Grid 只在 `/table` 和用到表格的 `/templates` 里用，改为可选 peer 依赖；以后的重依赖单独成包或懒加载。
  - **P4** 首屏不出现的大块懒加载（值帮助、个性化、适配筛选、新建对话框、Excel 导出、图表视图）。
  - **P5** 主题用 CSS 变量，一个样式文件，总量设上限。
  - **P6** 元数据可以在构建时预编译成 JSON，浏览器里不必带 XML 解析器。
  - **P7** 体积上限进 CI：每个子路径一个上限，再按场景设上限（只用 `MicroChart`、列表页、对象页）。
  - **P8** 演示应用列表页和对象页的首屏 JS 总量和 LCP 设目标值，用端到端测试测。
  - **子路径**：`@rhfan2019/smart-kit` 按领域提供入口 `/context`、`/i18n`、`/theme`、`/util`、`/field`、`/filter`、`/variants`、`/table`、`/chart`、`/object`、`/page`、`/actions`、`/edit`、`/messages`、`/templates`。根入口 `.` 保留，从各子路径转导出；源码里各入口在 `src/entries/`，根入口 `src/index.ts` 只做转导出，导出清单只维护一处。
  - **加新组件的规则**：默认放进某个子路径；只有带来很重的第三方依赖或运行环境不同时，才新开包 `@rhfan2019/smart-kit-<名字>`。
- **本次落地**：P2、P3、P7 和子路径。P4、P6、P8 另行实施，届时更新本 ADR 的状态。
- **理由**：样式只有 7 KB（gzip），不拆；JS 是主要成本。保留源文件结构后，打包工具可以按模块整体丢弃没用到的部分，这是 Mantine、MUI 等成熟组件库的通行做法。
- **代价**：`dist` 里文件变多；子路径要和文档保持一致（`api.md`）。不装 AG Grid 时只能从不含表格的子路径引入，从根入口引入时打包工具仍会解析到 AG Grid。
- **状态**：采纳（2026-11-16）。P1、P2、P3、P5、P7 已落地；P4、P6、P8 待做。修订 ADR-004 的"单一入口"部分。
