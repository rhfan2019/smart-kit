# @rhfan2019/smart-kit

## 0.5.0

### Minor Changes

- 62ced7d: Unmanaged save, `$batch` and fixes from the first applications (D51, ADR-034). smart-kit-server: `EntitySetHooks.create` / `update` / `delete` let the application store the entity while the service keeps the protocol; `unitOfWork` with `createKyselyOnClient` runs the service inside the host's transaction; `$batch` in the OData 4.01 JSON format with atomic change sets; `authorize` for every request. smart-kit-core: `DataProvider.batch`, `writeAll`, `batch: 'json'` on `ODataV4Provider`. smart-kit: several writes of a page are one batch request; responsive tables pop columns in the way sap.m.Table does; object page footer actions at the right, first section title hidden, `onActionDone`; list report `navigationParameter` and per-entity-set table settings; grid tables are named and their screen reader texts translated. smart-kit-cli: an empty schema is accepted. `NavigationAdapter.toCreate`: with it, "Create" of a list without draft opens the object page in create mode instead of a dialog. Hooks and unmanaged saves get Edm.Decimal / Edm.Int64 values as numbers also when the client sent them as strings (IEEE754Compatible).

## 0.4.0

### Minor Changes

- 204d8c6: SAPUI5 alignment, stage 1 (docs/31, D37). **Breaking**: the general controls, message controls, cards and enums move to their SAPUI5 module paths with the prefix replaced, one class per module, default export (`import MessageBox from '@rhfan2019/smart-kit/m/MessageBox'`, `import { ValueState } from '@rhfan2019/smart-kit/ui/core/library'`); the subpaths `/controls`, `/messages` and `/cards` are removed and the root entry no longer exports these names. Types follow UI5's TypeScript names (`$MessageStripSettings`, `MessageStrip` as the instance type, `Timeline$FilterSelectionChangeEvent`). Properties, defaults, events and methods follow the SAPUI5 1.154 API; see the migration list in docs/25.
- 89ac1fc: SAPUI5 alignment, stage 2 (docs/31, D38). **Breaking**: the annotation-driven building blocks follow sap.fe.macros (`v4/fe/macros/Table`, `TreeTable`, `FilterBar`, `VariantManagement`, `Field`, `Form`, `Chart`, `MicroChart`, `MessageButton`, `Share`, `KPITag`, `Paginator`, `fcl/FlexibleColumnLayoutActions.block`) with `contextPath` / `metaPath`; layouts follow sap.f / sap.uxap / sap.m (`f/DynamicPage` + `DynamicPageTitle` + `DynamicPageHeader`, `f/FlexibleColumnLayout`, `uxap/ObjectPageLayout`, `uxap/AnchorBar`, `m/Table`, `m/GenericTag`); hooks are in `kit/`. The subpaths `/field`, `/filter`, `/variants`, `/table`, `/chart`, `/object`, `/page`, `/actions`, `/edit` are removed and the root entry exports only the infrastructure. `DraftMarker` and `OverflowActions` are removed (use `m/ObjectMarker`, `m/OverflowToolbar`). `Field` fires `change` when the value is committed and `liveChange` while typing, as UI5. See the migration list in docs/25.
- 360b348: SAPUI5 alignment, stage 3 (docs/31; docs/29 §4 P1-2, P1-3): `Aggregation.CustomAggregate` is read (`AggregationModel.customAggregates`) and custom aggregates are requested as Fiori elements requests them, `aggregate(NetAmount)` instead of `NetAmount with sum as NetAmount`, in totals, charts, KPIs and cards; when the entity declares custom aggregates only those can be totalled. The list report chart (`v4/fe/macros/Chart`) sends FE's request (`buildChartRequest`: grouped by all dimensions and the units of the measures, groups sorted, `$count=true`, no `$orderby` and `$top` unless sorted), draws all measures as grouped bars (dimensions with the role Series split them into series) and, as FE, shows "Invalid data / Some measures have different units." instead of adding up amounts in different currencies. New core exports `buildChartRequest`, `aggregateMeasure`, `isCustomAggregate`, types `AggregateMeasure`, `ChartRequestOptions`; `ChartModel.dimensionRoles`.
- 360b348: SAPUI5 alignment, stage 3 (D39, docs/23 §10): totals and group subtotals follow Fiori elements 1.154 — only the analytical table (`v4/fe/macros/Table` `type="AnalyticalTable"`, `SmartListReport` `tableType="AnalyticalTable"`) groups with subtotals and shows totals; the responsive table groups without counts or subtotals; the grid table (`GridTable`, the default) neither groups nor totals. Only custom aggregates (`Aggregation.CustomAggregate`) are totalled (`canTotal`; no "numeric property with sum" fallback); without `UI.PresentationVariant/Total` an analytical table totals all of them. smart-kit-server accepts `aggregate(Name)` without `with` for declared custom aggregates (the property of the same name, summed, or with the first `SupportedAggregationMethods` entry when sum is not listed). As in FE, the unit is aggregated with the measure (`aggregate(NetAmount,Currency)`; subtotals `groupby((Group,Text),aggregate(NetAmount,Currency,$count as …))`, no longer grouped by the currency): a total over several currencies shows "Show Details", a popover "Totals" / "Subtotals" with the amount per currency (`buildTotalsRequest` option `byUnit`, `TotalAmount.multiUnit`); an empty `PresentationVariant/Total` totals nothing (`PresentationModel.hasTotal`). smart-kit-server returns the unit of a custom aggregate named in `aggregate()` (the currency, or null for several).
- 360b348: SAPUI5 alignment, stage 3 (docs/31, D40). **Behaviour changes** to match Fiori elements 1.154 on the list report: draft lists show own drafts and new drafts under "All" with the six editing-status options (filter key `$editState`, FE ids); each view applies its complete SelectionVariant; the search field is shown unless `Capabilities.SearchRestrictions/Searchable` is false; `Common.FilterDefaultValue` gives default conditions; value helps are filtered by In/InOut/Constant parameters and write Out/InOut back; `Common.IsDigitSequence` input is padded to MaxLength; unbound actions with `Core.OperationAvailable` false are disabled.
- 5e909b2: SAPUI5 alignment, stage 4 tail (docs/31, D45). The analytical table reads its first page, grand total and count in one Fiori elements style `$apply` (`concat`), sorts only by grouped or aggregated properties, reads non-groupable columns per row, and shows the basic search only with the `search` transformation; smart-kit-server supports `concat`, `orderby`, `skip`, `top` and `identity` in `$apply`. Value helps follow `Common.ValueListReferences` / `ValueListMapping` (optional `DataProvider.valueListService`); parameterized entity sets (`Common.ResultContext`, SelectionVariant Parameters) work in the list report. As real FE 1.154: constant `UI.Criticality` row highlights are not shown, date-times show seconds, personalization offers FE's property list, toolbar actions overflow only when they don't fit, delete confirmations have singular texts. See docs/25.
- 66c48a3: SAPUI5 alignment, stage 4 (docs/31, D43). **Behaviour changes** to match Fiori elements 1.154 on the list report: inline actions get one column each and are disabled instead of hidden; data point, field group, connected fields and contact columns as FE; the row highlight comes from `UI.LineItem@UI.Criticality` (a property's `UI.Criticality` no longer colours cells); toolbar actions in FE order with action groups, copy, `CreateHidden` / `DeleteHidden` and per-row `Deletable`. Filters use the strictest `FilterExpressionRestrictions` and the FE operators, all FE semantic date operators (relative dates as `ge … and le …`), `UI.HiddenFilter`, `tolower` with `Capabilities.FilterFunctions`; conditions of `UI.Hidden` properties are dropped; value helps with qualifiers, FE descriptions and request shapes. Values: `mailto:` / `tel:` links, `HTML5.LinkTarget`, `Common.ExternalID`, `Common.Masked`, `Common.Timezone`, streams; `$expand` selects the target keys and lists no longer select the ETag property. Views and charts: SelectionPresentationVariant → PresentationVariant → LineItem, chart-only pages, FE chart types, automatic analytical / tree tables, `UI.KPI` tags. `Core.IsURL`, `Common.IsUpperCase` and `PropertyModel.criticality` / `isUrl` / `isUpperCase` are removed (D41). See the migration list in docs/25.
- a8a942b: SAPUI5 alignment, stage 5 (docs/31, D46). **Breaking**: the page templates follow sap.fe.templates: `SmartListReport` → `v4/fe/templates/ListReport`, `SmartObjectPage` → `v4/fe/templates/ObjectPage` (default exports); the `/templates` subpath is removed. Their props are the Fiori elements manifest settings with the same names, nesting and defaults (`initialLoad`, `liveMode`, `variantManagement`, `views`, `controlConfiguration` › `tableSettings` / `columns` / `actions`, `content.header` / `body.sections` / `footer`, `sectionLayout`, `editableHeaderContent`, `additionalProperties`, …); custom columns, actions, sections and facets are React render functions / handlers under the same keys. Defaults as FE: `liveMode` false, `initialLoad` 'Auto', responsive table when `tableSettings.type` is not set, FE page sizes, NewPage creation on draft lists, view tab counts via `/$count`, no "Edit Header" dialog on the object page (header facets are edited in a "Header" section). See the migration list in docs/25.
- ef4ffd0: SAPUI5 alignment, stage 6 (docs/31, D47). **Breaking**: the data-only micro charts are the nine sap.suite.ui.microchart controls (`suite/ui/microchart/BulletMicroChart`, `RadialMicroChart`, `HarveyBallMicroChart`, `DeltaMicroChart`, `ColumnMicroChart`, `LineMicroChart`, `ComparisonMicroChart`, `AreaMicroChart`, `StackedBarMicroChart` and their element classes) with the UI5 properties; the personalization dialogs are `m/p13n/Popup` with `SelectionPanel`, `SortPanel`, `GroupPanel`; `m/QuickView` (+ `QuickViewPage`, `QuickViewGroup`, `QuickViewGroupElement`); `f/…AccessibleLandmarkInfo` modules. The building blocks gain the sap.fe.macros 1.154 members (Table / TreeTable: `rowCount`, `variantManagement`, `quickVariantSelection`, `massEdit`, `enablePaste`, `actionOverflowGroups`, presentation / selection variant methods; Chart: personalization, variant management; FilterBar: variant key methods; Field: `semanticObject`). Behaviour as FE: the grouped analytical table is a collapsible hierarchy (`$$aggregation` group levels, one `$apply` per level), the list report ignores `rowCountMode` / `rowCount` (grid tables are Auto), NewPage creation on draft lists asks for the non-computed keys first ("New Object" dialog), the chart shows its personalization buttons by default, object page header actions follow FE's order. See the migration list in docs/25.
- 8af2d4c: SAPUI5 alignment, stage 7 (docs/31, D48). The remaining Fiori elements 1.154 settings that do not need the SAP runtime: object page sub-tables take the same table settings as the list report (shared mapping); header, footer and section toolbars use the FE overflow priorities, groups, separators, menu default actions and FE's emphasis rules (`isPrimaryAction`, UI.Emphasized, Criticality); `shareOverflowPriority`; action `defaultValuesFunction` and `afterExecution`; table action groups with `defaultAction` (split button), toolbar `template` content, column overrides, `showDataFieldsLabel`, cell merging, `exportSettings`, `aiNotice`; `useSemanticDateRange` and filter field `settings`. Behaviour as FE: date filter fields without `Capabilities.FilterExpressionRestrictions` offer only the basic operators (no relative dates); the action parameter dialog renders a field per parameter from its annotations (fixed values, value help, multi-line, `UI.ParameterDefaultValue`, `Common.FieldControl` Mandatory) and sends typed values; table micro charts show only the chart by default. smart-kit-core: `ActionParameterModel` and the action parameter helpers. See the migration list in docs/25.
- f7d8b64: New subpath `@rhfan2019/smart-kit/controls` with general controls that use the SAPUI5 1.154 names, properties, events and methods (ObjectStatus, IllustratedMessage, ProcessFlow, Timeline, UploadSetwithTable, DynamicDateRange, SelectDialog, ViewSettingsDialog, Wizard, IconTabBar …); message controls MessageToast, MessageBox, MessageStrip, MessageView, MessagePopover in `/messages`; `SmartTable tableType="TreeTable"` for `Hierarchy.RecursiveHierarchy` with a ref API like sap.ui.table.TreeTable (core: `buildHierarchyRequest`, `hierarchyOf`, `hierarchyNodeOf`).

## 0.3.0

### Minor Changes

- 42ec477: Fixes for the first consumer (docs/25): grid tables group with row counts and subtotals in group header rows; texts name the record type instead of "object" ("User created.", `typedText`); a failed view save shows the store's error in the dialog and `VariantStore.canSave` / `canSave` / `canSaveVariants` hide Save, Save As and Manage; the view menu closes before its dialogs open; `exportable`, `onBeforeExport` (can cancel) and `onExported` on `SmartTable` and `SmartListReport`; `refreshToken` on `SmartListReport`; `MemoryProvider.setRows` for rows computed by the host; `SmartObjectPage` `partialHeaderEdit` and `share`, a failed partial edit cancels any edit session, initials avatar from `UI.HeaderInfo/Initials` (round for `Communication.Contact`); `importance` on custom columns, wider pop-in labels and `--sk-sticky-top` for host sticky bars.
- 42ec477: Relative dates in date filter conditions (today, yesterday, this / last / next week, month, quarter and year, last / next X days, year to date): views store the operator and it is resolved against today when the list is read. Value list values in filter fields follow `UI.TextArrangement` (`TextOnly` hides the code). `FlexibleColumnLayout` has column separators with arrows that switch the ratios (new layouts `TwoColumnsBeginExpanded`, `ThreeColumnsEndExpanded`, `ThreeColumnsMidExpandedEndHidden`, `ThreeColumnsBeginExpandedEndHidden`) through `onLayoutChange`. Themes switch with `data-sk-theme` / `data-sk-density` (the former `data-theme` / `data-density` still work unless `<html>` has `data-sk-theme`); new stylesheet `@rhfan2019/smart-kit/styles.layered.css` inside `@layer smart-kit`; the React entries start with `'use client'`.
- 42ec477: smart-kit-server: `$filter` supports the lambda operators `any` / `all` over collection navigations (with `$it` and nested variables), and a data scope may use them (`_ScopeKeys/any(k: k/CompanyCode eq '1000')`); the scope applies to reads, `$count`, key reads, `$expand`, navigation paths and lambdas of other sets, `$apply` and writes (TECH-054). Navigation joins can come from the storage mapping (`entitySets.<Set>.navigations.<name>.on`). New `createKysely(pool, { statementTimeout, keepSettings })` builds Kysely on the host's `pg` pool with UTC sessions and a statement timeout (TECH-066). smart-kit-cli: navigations without a foreign key (views) can be declared in `smart-kit.config.json` (`navigations.<name>` with `from`, `to`, `on`, `toMany` or `toOne`, `partner`); they are generated into the CSDL and the storage mapping, and `smart-kit check` reports declarations whose tables, views or columns do not exist (TECH-055); `checkDeclaredNavigations` exported.
